# Documentation System and i18n

The repository maintains extensive developer documentation under `docs/` (architecture, subsystem pages, cookbook, tutorial, catalogs, and i18n guidance), paired English/Simplified-Chinese pages across the corpus, generated catalogs and graphs, and a set of `verify-*` gates that CI runs exhaustively.

## Bilingual pairing contract

Every document in scope is maintained in English and Simplified Chinese. A pair is three sibling files: the English `foo.md`, the Chinese `foo.zh.md`, and a consistency record `foo.i18n.yaml`, all in the same directory — no locale directories. The consistency record holds the full git blob hash of each side as of the last time the two were confirmed to say the same thing. The Chinese file always links back with `[English](foo.md) | 中文`; heading depths, list kinds, table shapes, semantic link targets, and verbatim code blocks must mirror one to one across the pair.

Scope covers the root `CONTRIBUTING.md`, `BRAND_GUIDELINES.md`, and `SAFETY.md`, every non-vendor README, and every active document under `.agents/notes/**`, `docs/**`, and `python/**`. Excluded (never paired) are `docs/AGENTS.md` and agent-instruction symlinks (English only), `docs/i18n/terminology.md` and `style-samples.md` (bilingual by construction), `translation-prompt.md` (machine-consumed verbatim), and the frozen `.agents/notes/archived/` tree.

## The pairing gate

`pnpm run verify-translation-pairing` (part of `doc-sync`) enforces the contract mechanically: every in-scope document has a complete pair; every pair artifact has all three files with recorded blob hashes matching current contents; the Chinese side and every authored English source carry their switchers; the structural signature matches in order. `verify-translation-pairing --list` prints the pairing state of every document, and `--write <pair>` re-records confirmed hashes — that yaml diff is the reviewable act of confirming consistency. A PR that leaves a pair out of sync goes red in CI.

## Generated catalogs and graphs

Several documentation artifacts are generated and verified fresh as part of `doc-sync`:

| Artifact | Generator | Gate |
| --- | --- | --- |
| `docs/tool-catalog.md` — every model-facing tool schema | `scripts/gen-tool-catalog.ts` (boots each tool plugin and reads `ctx.tools.schemas()`) | `verify-tool-catalog` |
| `docs/config-catalog.md` — every config field | `scripts/gen-config-catalog.ts` | `verify-config-catalog` |
| `docs/persistence-catalog.md` — the persisted session event vocabulary | `scripts/gen-persistence-catalog.ts` | `verify-persistence-catalog` |
| `docs/event-producer-consumer.md`, `docs/capability-seams.md` — event and service graphs | `scripts/gen-doc-graphs.ts` | `verify-doc-graphs` |

The tool catalog is generated by booting each tool plugin on a real context and reading `ctx.tools.schemas()`, because a tool schema is not statically knowable (runtime-spread enums, config-driven names, raw-JSON-Schema MCP tools). A completeness guard globs `packages/*/tool-*` and fails if any package is missing from the boot manifest.

## Other documentation gates

- `verify-md-wrap` and `verify-md-links` — line-wrap and internal-link validation (the latter also checks the paired `.zh.md` files).
- `verify-mermaid` — Mermaid fence validation.
- `verify-subsystem-pages` — every package group has a subsystem page.
- `verify-doc-budgets` — documentation length budgets.
- `verify-doc-site-fragments` — the documentation-site fragment contract.
- `verify-export-jsdoc` — exported symbols carry JSDoc.
- `doc-typecheck` — documentation code fences type-check.
- `test:docs` — the build-free documentation aggregate (`doc-quick`).

## Website

The documentation site is built from the same corpus: `docs:build` runs `tsx website/build.ts` followed by `verify-doc-site-fragments`; `docs:dev` runs the `@deepseek-ai/website` package dev server; `docs:check` runs the doc-site specs and the build. `docs:build:mpa` produces the multi-page-application variant.
