# 自动记忆提取

[English](memory-extraction.md) | 中文

**压缩触发的记忆提取** —— 每次检查点之后，一个有界、失败开放的流水线把检查点日志范围中用户撰写的文本变成持久事实，写入 `retain`/`learn` 使用的同一项目记忆库。移植自 Maka 的自动记忆提取触发器（见 `port_maka.md` No. 2），打包为单个包 [dsh-memory-extraction](../../packages/memory/memory-extraction)：一个主机平面 Cordis 插件，无工具、无提示区段 —— DSH 显式的 `retain`/`learn`/`memory_edit` 表面仍是面向模型的路径。

设计上在 Maka 慷慨之处刻意保守：移植保留了 Maka 的承重规则（证据仅限用户撰写文本、有界且失败关闭；提案 → 准入 → 规范化 → 再准入，逐字核验引文并确定性拒绝密钥；每个范围最多 3 次辅助模型调用；每会话游标只推进到已提交边界，空范围仍然推进），并把失败调度简化为每个范围一条待处理重试，之后丢弃。

## 为何在主机平面

插件观察**每个会话**的 `compaction/summary` 事件。DSH 的作用域过滤器全局接纳无作用域监听器（主机 `ctx.on('session/event')` 接收所有会话的事件），而代理作用域的监听器只能看到自己的会话。`memory_extraction` 控制单元（每会话的游标、回执和待处理失败账本）每进程只打开一次 —— 按会话安装的行会在单元打开时冲突。这两个原因都把该行钉在**主机组合**中；没有按会话键控的东西。

## 流水线

1. **触发。** `compaction/summary`（由 [dsh-compaction](../../packages/compaction/compaction) 在检查点发出），以 `seq` 为边界。运行在每会话队列上调度，同一会话的两次检查点不会交错；每次触发按操作 id `memory_` + sha256(`{sessionId, trigger, boundarySeq}`) 幂等。
2. **证据投影。** 只有 `source.kind === 'user'` 的 `user/message` 事件才是证据；助手文本仅作解读上下文；工具调用/结果、推理块和插件检查点保持不透明（它们可能包含工具输出或注入指令）。记录经过规范化，单条上限 4 000 码点， JSON 载荷 12 000 字符，记录数 64（沿用 Maka 的数字）；无法容纳最小上限的证据集失败关闭（跳过该范围，绝不静默截断）。
3. **提案。** 一次辅助调用在有界证据上要求 complete/`search_required`/ `cannot_resolve`，证据被标示为**不可信数据**并给出 JSON 输出契约。 `search_required` 触发同会话本地化搜索（上限 7 轮、12 000 字符）和第二次调用；每次 `cannot_resolve` 使该范围以已提交-跳过收尾。
4. **准入。** 每个提案条目只有在内容符合策略（密钥脱敏：`sk-`/`ghp_`/`AKIA` 式模式）且每条引文（最少 4 字符）逐字存在于所引用的有界证据中时才被接纳。规范化之后对引文再次交叉核验。
5. **规范化。** 第三次调用把候选 id 映射为 accepted/rejected/最终内容；被接纳的输出对同一证据重新核验。每个范围的模型调用总数：**3**，每次受 `timeoutMs` 约束（默认 60 秒）。
6. **提交。** 通过的事实以 `source: 'memory_extract'`、可配置重要性（默认 `0.5`）和指明会话与检查点的来源上下文写入。提交前对记忆库做去重探测，跳过规范化后重复的内容。写入顺序是 **条目 → 游标 → 回执**：游标与回执之间崩溃永远不会重复处理该范围（下一次触发从新游标开始）；条目与游标之间的崩溃通过去重探测自愈。
7. **失败调度。** 空范围（或仅有事件而无用户证据的范围）推进游标并写 `skipped` 回执，零模型调用。失败范围写入一条待处理失败记录（`fromSeq`/ `throughSeq`/覆盖哈希/尝试次数），下一次触发**重试一次**；第二次失败丢弃该范围（游标推进，`discarded` 回执）。覆盖经过哈希核验，重试绝不针对已变化的数据运行。

失败开放：运行时捕获所有错误、记录日志，绝不让提取失败进入触发它的那个轮次。

## 存储

`memory_extraction`（版本 1，表 `cursors`/`receipts`/`failures`）位于配置的存储后端（默认 `sqlite`，经 `storage.backend.<name>.kv.open`）的 kv 面中，与[图控制单元](../subsystems/graph.zh.md) 同一约定。单个 `KvUnit`、单一写入链、无 SQL 事务：多步原子性是进程级的，通过写入顺序与幂等补偿，而非回滚。

## 配置

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 总开关；`false` 使插件保持惰性 |
| `backend` | `sqlite` | 承载控制单元的 kv 存储后端 |
| `provider` / `model` | 会话路由的请求头 | 辅助模型覆盖（建议用廉价模型） |
| `importance` | `0.5` | 提取事实的记忆库重要性 |
| `dedupe` | `true` | 提交前探测记忆库以跳过重复 |
| `excludeSubagents` | `true` | 子会话压缩永不提取（每次模型调用前重新检查） |
| `timeoutMs` | `60 000` | 单次辅助调用超时 |

主机组合行参见 [示例补丁](../../apps/cli/config/examples/memory-extraction/cordis.yml)，内部布局参见包 README。
